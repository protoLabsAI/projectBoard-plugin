- **When one source issue is split across several cards, only the last open slice closes it.** `_inject_source_issue_line` stamped `Fixes #N` on every same-repo PR whose card carried that `source_issue`, so the first merged slice closed the umbrella issue out from under its siblings (nerdsville-site#6 closed by slice PR #39/#40). The PR body now gets `Refs #N` instead whenever ANY other open (non-done, non-cancelled) card on the board shares the same parsed source issue; only the sole or last open slice keeps `Fixes #N`. A store read error while scanning siblings fails SAFE to `Refs` — an uncertain read never closes an issue early. A second closing path is also plugged: the squash commit subject comes from the PR title (`feat: {title}`), so a card titled `fix: #6.3 address review` made GitHub read `#6` as a closing reference. PR titles now neutralise any `#n` that follows a closing keyword or a conventional-commit prefix and is not the card's own clean source-issue reference (`fix: #6.3` → `fix: 6.3`). Cross-repo source issues still get `Refs <full-url>` as before.
