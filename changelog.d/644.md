- **A `create_from_plan` item with `priority: 0` now keeps priority 0 — beads' HIGHEST rank — instead of being silently demoted to the 2 default (#644).** The batch path read each item as `int(item.get("priority", 2) or 2)`, and because 0 is falsy the `or 2` promoted the most urgent card to 2, reordering the loop's claim queue. Only a missing key or an explicit `null` now falls back to 2; an explicit 0 (or any other rank) is passed through. The raw value reaches `validate_priority` inside the per-item try, so a non-int (`""`) or a bool (`False`, which `int()` would quietly make 0) fails THAT item with a named reason and lets the rest of the batch proceed — the all-or-report contract — rather than aborting the whole batch on an uncaught `ValueError`.
