- **A first-class setter for the per-card `merge-hold` operator veto (#532).** The
  `merge-hold` label is the documented operator veto on the auto-merge edge — a green,
  verified, reviewed PR the operator still wants to QA by hand — but it was only ever
  READ. No tool, no store verb and no HTTP route could add or remove it, so on an
  `auto_merge=true` board nobody but a human running `br label add` could make one card
  human-merge-only. Now `board_hold_merge(feature_id, reason)` places the veto and
  `board_release_merge_hold(feature_id)` lifts it, each writing one audit comment on the
  bead (`merge-hold set: <reason>` / `merge-hold released`); the REST twins are POST and
  DELETE `/features/{fid}/merge-hold`. A hold is valid in any non-terminal state
  (backlog/ready/in_progress/in_review/blocked) so it can be set before a card is ever
  dispatched; a done/cancelled card or an unknown id is refused with a readable error and
  nothing changes, and re-holding an already-held card is idempotent (no second comment).
  `board_get_feature` now exposes `merge_hold: bool`. Auto-merge behaviour and defaults
  are unchanged — the existing merge-posture / auto-merge edge already honours the label
  (`merge-hold (operator veto)`); this only adds the setter that was missing.
