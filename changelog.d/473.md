- **An external QA panel's FAIL now sends the card back to a fix round (#473).** The repo's
  own review bot (protoreview's "Vera") can FAIL a PR that the board's in-process gate
  passed. On bd-524n (protoAgent#3698) it did: CHANGES_REQUESTED, a `QA panel` check run
  failing, a `Review at head` status failing, and a confirmed major in the review's findings
  JSON. Nothing read any of it. The card sat `in_review` for seven hours and re-ran the
  ~12-minute merged-state gate on every move of main until `merged-verify budget (5) spent`.
  Now the reconcile checks first, with one `gh pr view --json headRefOid,reviews,statusCheckRollup`
  per in-review card. The panel has failed the head when the latest marked review from a
  configured reviewer (`<!-- protoagent-qa-review head=<sha> verdict=FAIL … -->`) names the
  current head, or when the panel's check run or status fails there without a PASS review
  at that head. When it has, the card goes back to a fix round on the same PR. The blocking
  findings (blocker/major, confirmed or verified, each with `file:line`, claim and evidence)
  go on the bead and lead the next prompt beside the PR diff, and the head is stamped
  `ext-review-bounced:<sha>`. That happens once per head: the same head failing again is
  held, and the operator is told once. A new push re-arms it. A check or status fail with
  no findings review is held, never bounced. Nothing is bounced under a live round. The
  external rounds are bounded by `review_fix_max` in their own `budget:ext-review-fix`,
  which the gate's clean verdicts don't reset, and when they run out the card is blocked for
  a human. While the FAIL stands, the pass runs no rebase, no merged-state gate and no merge,
  so no merged-verify budget is spent. The reviewers, the marker and the check and status
  names are configurable (`external_review`, top level or per project; `false` turns it off).
- **Operators can bounce a card for review without the webhook secret (#473).**
  `POST /api/plugins/project_board/features/{fid}/review` (`{findings, escalate?}`) on the
  bearer-gated surface does what the signed `/plugins/project_board/features/{fid}/review`
  does. `board_requeue_feature` takes `escalate` too. All three run one shared bounce.
