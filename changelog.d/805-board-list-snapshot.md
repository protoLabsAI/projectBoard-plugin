- **`board_list` answers from the board's shared read snapshot instead of listing the store on every call (#805).** Each call used to run `br list` over the whole card history plus a `br show` per 100 live cards, and every one of those queued for the process-wide `br` lock behind the loop and the sweep, so on a busy host one call took 3 to 7 seconds. The tool now reads the same cached listing `GET /features` and `/cards` serve from: a call on an unchanged board runs no `br` and answers in milliseconds, and the `state`, `project` and `include_archived` filters and the `next_action` fields are the same as before. A board tool call that wrote to the store (`board_update_feature`, `board_block_feature`, …) is always followed by a listing taken after that write, so an agent never reads its own change back as missing. When the loop or another process changed the board and the store is too busy to list it within 1.5 seconds, the call answers from the previous listing and ends with one line saying how old it is and to call again. `board_list(project=…)` for a project whose folder is missing is still refused by name.
