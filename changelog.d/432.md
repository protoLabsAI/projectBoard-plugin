A delivered task now shows its deliverable wherever the card is read. `GET /features` and the
board listing read every task's `deliverable` as empty, and `board_get_feature` had no such
field, so an intact delivery looked lost and an agent set about "repairing" it. Repeating a
delivery the task already carries is now a no-op instead of an error. A different deliverable
for a task already in review is refused with a message naming who delivered it and how to
replace it. A deliverable that fails to write now fails the delivery and leaves the card in
progress for a retry, instead of moving it to review empty. A task drive whose agent delivered
mid-turn, or whose card was pulled back under it, now ends cleanly instead of raising out of
the drive.
