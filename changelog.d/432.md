A delivered task no longer reads as empty. `GET /features` listed every task with an empty
`deliverable`, and `board_get_feature` had no such field, so an intact delivery looked lost and
an agent set about "repairing" it. Task rows in the listing now carry `delivered` (true only
while the task is in review or done), `deliverable_chars`, `delivered_by` and a short
`deliverable_preview`, and the single-card reads return the full text. A task delivery now
lands whole or is refused. A failed write never leaves a card in review without its
deliverable, and an empty delivery is refused. Two deliveries racing on one card no longer
both land. Repeating a delivery is a no-op, and a different one for a task already in review
is refused. A task drive no longer blocks a card its agent already delivered, and never dies on
a failed or timed-out `br` call. Tasks now use the requirement ledger: a deliverable's exact
`## Requirements` rows close the items they cover, ignoring code fences and hedged rows. A
rejection reopens them, and the next round's prompt leads with its feedback. `board_get_feature`,
verification results and the Board view's task drawer name what is still open, but open items
never block a delivery or an approval.
