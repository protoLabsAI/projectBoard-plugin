A delivered task no longer reads as empty. `GET /features` listed every task with an empty
`deliverable`, and `board_get_feature` had no such field, so an intact delivery looked lost and
an agent set about "repairing" it. Task rows in the listing now carry `delivered`,
`deliverable_chars`, `delivered_by` and a short `deliverable_preview`, and the single-card reads
return the full text. Repeating a delivery the task already carries is a no-op instead of an
error. A different deliverable for a task already in review is refused, naming who delivered
it and how to replace it. A deliverable that fails to write fails the delivery and leaves the
card in progress for a retry. A task drive whose agent delivered mid-turn, or whose card was
pulled back under it, now ends cleanly. Tasks now use the requirement ledger too: a
deliverable's `## Requirements` section closes the items it covers, and `board_get_feature`
and verification results name any still open. The Board view's task drawer lists each item's
status above Approve/Reject, and approving with items still open shows which ones. Open items
never block a delivery or an approval.
