- **A card on a branch that exists only on the remote no longer loses finished work as "no commits vs base".** `open_pr` counted the coder's commits as `git rev-list <base>..HEAD` using the bare branch name, and it ignored git's exit code. So on a board checkout with no local branch for the base (an epic branch such as `epic/interactive-answers`, created only on the remote), git errored and the count read as 0. The finished commit was raised as `NoChangesError`, escalated up every rung, and the card was blocked as terminal. Three protoAgent ADR 0118 cards lost verified work this way. It now counts against `origin/<base>` first and the local `<base>` second, the same order `create_worktree` and `commits_ahead` use. When neither resolves, it raises `WorktreeError` (an infrastructure failure) rather than reporting an empty diff.
