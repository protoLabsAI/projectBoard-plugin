The board no longer destroys a worktree that holds work existing nowhere else. A coder that
died before its candidate was promoted left the only copy of its implementation in that tree,
and the next re-dispatch force-removed it and deleted its branch. Every other edge that ends a
tree did the same: the merge, cancel, done and sweep reaps, a drive's terminal block or cancel,
and shutdown. Now each of them first saves the tree's work to a new
`stranded/<tree>/<UTC stamp>` branch, with the repo's hooks off. It never overwrites an
existing branch and never fails on a name it chose, and it checks that the branch really holds
the work before the tree goes. The card gets a comment naming the branch, its diffstat and how
to inspect or cherry-pick it, and the build carries on. Work means any uncommitted change, plus
any commit the tree's HEAD or branch holds that no other ref does. That covers the verified
candidate committed on the card's own branch and a detached HEAD, but not history that is
already published through a rebase or a squash-merge. A tree git can no longer read is moved
aside with its files intact. Only work that genuinely can't be saved stops a card, as
`stranded-work`, with the tree kept whole; a nested git repository is the usual case. The
coder's session scratch and the board's `node_modules` links don't count. That link is also no
longer committed into PRs in repos whose ignore file only has `node_modules/`. The coder's
brief no longer tells an edit-only coder to push. It says the loop commits, pushes and opens
the PR, and only mentions pre-PR checks when a gate is configured.
