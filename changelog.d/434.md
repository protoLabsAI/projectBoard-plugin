The board no longer destroys a worktree that holds work existing nowhere else. A coder that
died before its candidate was promoted left the only copy of its implementation in that tree,
and the next re-dispatch force-removed it and deleted its branch. The merge, cancel, done and
sweep reaps and a shutdown did the same. Now each of those edges first saves the tree's work
to a new `stranded/<tree>/<UTC stamp>` branch, never overwriting an existing one, and checks
the branch really holds it before the tree goes. The card gets a comment naming the branch,
its diffstat and how to inspect or cherry-pick it, and the build carries on. Only work that
can't be saved stops a card, as `stranded-work`, with the tree kept intact. Work means any
uncommitted change, plus commits on a candidate branch that no other ref holds. The coder's
session scratch and the board's `node_modules` links don't count, and that link is no longer
committed into PRs in repos whose ignore file only has `node_modules/`. The coder's brief no
longer tells an edit-only coder to push. It now says the loop commits, checks, pushes and
opens the PR.
