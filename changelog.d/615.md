- **Configure folds the last two tabs into one Maintenance tab, completing the five-tab overhaul (settings overhaul S5, #615).** The old **Automation** and **Security** tabs become a single **Maintenance** tab, placed last, so Configure is now exactly five tabs in the order you meet a board — **Overview, Projects, Coders, Review & merge, Maintenance** — one per operator question. Maintenance holds the five things nobody needs to get started: download-the-board-tool (`br_autofetch`), update-checkouts (`base_refresh`), the pre-PR check command (`local_gate_cmd`), and the two secrets (`webhook_secret`, `npm_token`). Each field's help now says *when* you would reach for it in one sentence; download-the-board-tool explains in plain words that `br` is the board's card database tool, and each secret says what it unlocks (the public merge/check/review update routes, or private-npm release checks) — their values are stored through the host's secret settings path and are never shown. The tab carries `apply: live` (core protoAgent #4489 applies a save to the running member; older hosts ignore the key); it stays a generic schema tab, so the secrets keep the host's secret path. docs/console-settings.md is rewritten to the final five-tab layout, one section per tab.
