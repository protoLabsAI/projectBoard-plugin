- **New Review & merge tab lays out what happens after a pull request opens as an ordered pipeline (settings overhaul S4, #614).** **Settings → Plugins → Project Board → Configure → Review & merge** (same id and deep link) is now a plugin-owned page that reads top to bottom as four steps in the order a PR actually travels them — **Review → CI → Rebase → Merge** — so someone new can tell from the page alone what the board will do. Each step is a card with an on/off switch and its attempts as small steppers bounded by the manifest min/max; turning a step off greys out and disables its dependent sub-settings. Review carries the required-review switch, a **workflow** picker, a **reviewer** picker (both of configured values, with a free-text fallback so a board whose value isn't listed is never stranded), an advisory-review-on-open switch and a fix-attempts stepper. CI carries bounce-failing-checks with rerun and fix steppers; Rebase carries update-with-base-changes and a conflict-fix stepper; Merge carries auto-merge with a merge-method picker (squash / merge commit / rebase), a hold-after-failed-checks stepper and the reconcile-PRs switch. Below the steps, a **Dependent cards** two-way radio sets whether a blocked card starts when its blocker **merges** (safer — builds on landed code) or **opens a pull request** (faster — builds on unmerged code); shared foundation changes always wait for a merge regardless. Every change saves through the guarded settings route with an inline "Saved"; a restart-only knob also nudges the host (`protoagent:settings:restart-pending`, harmless until core support ships) and lists itself in a pending-restart callout by its plain label. The fifteen review/CI/merge scalar knobs moved off the Automation tab's generic settings list onto this page, which now owns them through the same PUT /settings boundary; the Review tab is no longer a generic schema tab. The page holds no board data — every read and write goes through the authenticated plugin-kit fetch after `initPluginView`, and colours come entirely from design-system tokens, so it works in light and dark.
