- **The console and REST API can release a conditional merge-hold, and re-setting a hold
  keeps its release condition (#856).** `DELETE /features/{fid}/merge-hold` now takes the
  same inputs as `board_release_merge_hold`: `force` (body `{"force": true}` or
  `?force=true`) overrides an unmet `until` condition, audited as an override, and `token`
  (body) is the npm token a private `npm:` spec needs (defaulting to the configured
  `npm_token`). Without force, an unmet condition is a 400 naming each unmet spec and the
  hold stays. `POST /features/{fid}/merge-hold` now accepts `until`. Re-holding a held card
  without `until`, from the route or from `board_hold_merge`, keeps the stored condition
  instead of clearing it; only the reason changes, and releasing the hold is what drops the
  condition. A forced npm gate re-check that brings a different token is no longer handed the
  throttled verdict cached without one.
