- **A restart mid-card no longer pays for the same coder work twice (protoLabsAI/protoAgent#5267).** When the host shut down while a coder was building a card, the board read the killed coder as a `transient` failure, spent a retry and slept the backoff into the shutdown; the next boot then reset the card to ready and rebuilt it from a clean base, although the unfinished work had been saved on a `stranded/…` branch. Now a dispatch the host killed on its way down (the error carries `host_shutdown=True`), or one that fails while the loop is stopping, ends the drive at once: no retry counted, no backoff, the card stays in progress. Shutdown records the `stranded/…` branch and its commit on the card (a `stranded:<sha>` label and a `stranded resume:` comment). On the next boot, if that branch still exists at that commit and still shares history with the card's base branch, the board recreates the card's worktree with the saved changes in it and requeues the card on its current tier, with a prompt that says to continue from the existing changes and re-run the checks. Nothing is published by the resume: the goal check, the pre-PR gate, CI and the review gate all run as on any build. A branch that is missing, moved, unreadable or diverged falls back to a fresh rebuild, with a log line naming the reason. The record is cleared when the card opens a PR or is cancelled. An older host, whose errors carry no `host_shutdown` attribute, is handled as before.
