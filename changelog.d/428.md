The pre-model guard (#339) no longer mistakes model work for an infra failure, or the reverse.
It counted streamed answer text as proof the model had run, but codex-acp sends its own "Model
metadata … not found" warning through that channel before calling the model. So a dispatch that
failed seconds after the session started looked like a real attempt, and the card climbed a tier
instead of blocking for triage. Only tool calls, thoughts and token usage count now. Separately,
the guard searched the whole failure message for words like "adapter" or "timeout", so a goal gap
that merely quoted them blocked as an infra failure instead of climbing. It now matches only
failures raised at the dispatch seam, never text a failure quotes.
