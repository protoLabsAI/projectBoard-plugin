The pre-model guard (#339) no longer counts an ACP adapter's own chatter as model work. codex-acp
sends a "Model metadata … not found" warning through the answer-text channel before it calls the
model. So a pre-model failure after that warning, such as an expired credential or a session that
never answers, looked like a real attempt and could climb a tier instead of blocking for triage.
(A provider refusing its model is already caught by its message, since #421.) Only tool calls,
thoughts and token usage that actually spent tokens count now. The guard also no longer searches
the whole failure message, so a goal gap that merely quoted "adapter" or "timeout" can't read as
an infra failure. It matches only failures raised at the dispatch seam.
