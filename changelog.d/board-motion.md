- **The Board view moves.** Kanban cards are keyed DOM nodes now, so when the loop moves a card it glides to its new lane (FLIP, ~440 ms, staggered when several move), new cards fade in, removed ones fade out, lane counts tick, and a card landing in done gets a check and a brief glow. `prefers-reduced-motion` gets an instant update with a short highlight instead. The board is live: it polls a new `GET /rev` change stamp (a few `stat`s of the beads store, no `br`) every 2 s and re-reads `/features` only when it moves; `/features` now carries an `ETag` and answers a matching `If-None-Match` with `304`. Building cards show the coder, elapsed time and last tool call. Operators can drag (pointer events, so it works in the desktop app) a backlog card onto on deck (`POST /ready`, rolled back with the gate's reason on refusal) or re-rank within backlog / on deck (`PATCH priority`); every drag has a keyboard twin (focus a card, **M**, or **Alt+→ / ↑ / ↓**), and the menu adds block / unblock. Building, in review and done stay loop-owned and say so. The in-chat board cards share the lane accents.
