- **A late or repeated CI or review result can no longer bounce a card twice, or bounce the wrong head.** The signed `POST /features/{fid}/ci` and `POST /features/{fid}/review` routes now require a `head_sha` naming the PR head the result is about (#767). The board checks it against the PR's live head and applies one result of each kind per head. A result for an older head, a redelivery at a head the card already acted on, or a result with no `head_sha` is acknowledged with `ignored` and changes nothing; the reconcile poll reads the PR's real state instead. Before this, a failure for head A applied to whatever head the PR had when it arrived, and a redelivered failure climbed the model ladder a second time. Nothing calls these routes today; a caller added later must send `head_sha`. See `docs/api.md`.
