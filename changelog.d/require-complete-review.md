- **A project can require a complete external review before the board auto-merges (`require_complete_review`).** The protoreview panel can finish a round with a finder down. Its `QA panel` check then concludes `neutral` ("Incomplete pass — not blocking", `hold:incomplete-coverage`) and its review marker carries `complete=false`. GitHub reads `neutral` as passing, so the board merged such a PR. protoAgent#4101 (card bd-vbyd.13) landed in `epic/interactive-answers` with part of its diff never reviewed. A project that sets `require_complete_review: true` (off by default, per `projects:` entry or top level) now holds the merge edge on an incomplete pass at the PR head. The card stays `in_review` reading `awaiting complete review (panel pass was incomplete)`, with one bead comment per head. The board posts one `@vera review` PR comment per head to ask for a full pass. The handle comes from `review_summon_handle`; blank holds without posting. A per-head marker on the comment keeps both a 30-second tick and a restart from posting it twice. Once a complete pass clears the head, the normal merge proceeds. With the setting off, nothing changes.
