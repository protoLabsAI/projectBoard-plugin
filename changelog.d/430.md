Saving a project in the Projects editor no longer re-runs its unchanged gate. The editor sends
every field back, so a conventions-only save of a project whose gate is the full test suite ran
that suite synchronously, for minutes, under the registry lock. Clients timed out with no
response, and a red suite refused an edit that had nothing to do with it. The gate now runs only
when a save sets a new gate command or moves the project to another repo. A base-branch-only
edit, or a project entry with no base branch, no longer triggers it; the loop's preflight covers
those. A gate that does run no longer blocks saves to other projects. If the project changed
meanwhile, the save is refused with a 409 rather than overwriting that change. A save that
outlives its connection (the fleet proxy allows 20s) reports its outcome through
`GET /projects`, and the editor picks it up. After a registry change the loop now re-checks
projects whose ready cards its gate preflight is holding. It used to strand those holds until a
restart. It also leaves the gate verdicts of untouched projects alone. The log records how every
save ended.
