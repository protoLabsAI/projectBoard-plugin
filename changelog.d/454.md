- **The Ready gate names the config key a repo root actually came from (#454).** On a
  multi-project board it now says `project_board.projects.<name>.repo` instead of
  `project_board.repo`. For a card whose project isn't registered, it says why it fell back
  to the flat key.
- **A flat `repo` left beside `projects:` is flagged (#454).** The new `legacy_binding`
  setup advisory (on `GET /status` and the host's setup-gap seam) calls out the ambiguous
  case, where the flat repo is another clone of a project's GitHub remote. It says which
  binding wins for which cards, and which projects still run a flat `local_gate_cmd`.
- **Cards orphaned on a project that no longer resolves are flagged and can be re-homed
  (#454).** An example is `default` left behind after a move to `projects:`. `board_list`
  rows carry `project_unresolved` and a `project_hint`, and `GET /status` lists them under
  `orphaned_cards`. `board_update_feature` and `PATCH /features/{fid}` take a new `project`
  argument that moves such a card in place and keeps its id and history. The move is allowed
  only while the card is backlog or ready, has no PR and has never been dispatched, and is
  refused with the reason otherwise.
