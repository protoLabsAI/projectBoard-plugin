- **The Coder routing Configure tab becomes "Coders" and gains a default-coder picker, capacity steppers and a collapsed Advanced block (settings overhaul S3, #613).** **Settings → Plugins → Project Board → Configure → Coders** (same id and deep link) keeps the per-coder cards and the ladder, and now leads with the controls the common case actually needs — no scrolling, no reading. A **Default coder** picker lists the configured delegates the routing read already returns, marks the chosen one "default" on its card, and saves through the guarded settings route; because that read only knows the delegates a ladder names, the control keeps a "Type a coder name…" free-text fallback so a fresh board with no ladder — or one whose coder no ladder names — can still set the required coder (the host roster, checked by setup, is the authority on whether a name resolves), with only an empty name refused inline. Two **Capacity** steppers — Parallel builds (`max_concurrent`) and Review-queue limit (`max_pending_reviews`) — use the manifest min/max and each carry a one-line consequence that updates as you step ("Up to 4 cards build at once"); both apply live with an inline "Saved", no restart. An **Advanced** section, collapsed by default, holds the six tuning knobs most boards leave alone — parallel coding sessions per build, try-solutions-until-tests-pass, the candidate test command (monospace, wrapped), alternative builds to compare, timeouts before asking to split a card, and check-acceptance-criteria-before-review — each a plain label with one sentence of help. Saving a restart-only knob nudges the host (`protoagent:settings:restart-pending`, harmless until core support ships) and lists the change in a pending-restart callout by its plain label. The nine scalar knobs moved off the Automation tab's generic settings list onto this page, which now owns them through the same PUT /settings boundary (Automation keeps only download-the-board-tool, update-checkouts and pre-PR checks until S5 relocates those); the allow/deny switches and ladder still ride PUT /routing. Every read and write goes through the authenticated plugin-kit fetch after `initPluginView`, and colours come entirely from design-system tokens, so it works in light and dark.
