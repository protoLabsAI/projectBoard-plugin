A coding card whose coder DECLINED every requirement no longer publishes as finished work
or stamps `Fixes` on its issue (#715). `declined` is a closed requirement status, so an
all-declined ledger passed the completion gate exactly like an all-`done` one — and opened
a normal PR: on protoAgent#4953 the coder declined all six requirements, shipped one docs
file, the PR still said `Fixes #4725`, review passed, and auto-merge would have closed the
issue with nothing built. A new `_all_items_declined` predicate (True only when the ledger
is non-empty and every item is `declined`, beside `_all_items_disposed`) now gates the
drive's publication seam: an all-declined coding card is blocked owner=operator (a terminal
hold the sweep never lifts) with each item's decline reason, no PR opens, and the worktree
is kept so the coder's prerequisite report survives for the operator's scope-reduction
decision. The PR opener stamps `Refs #N`, never `Fixes #N`, for an all-declined ledger, so
an operator who later unblocks or salvages the card references rather than closes the issue.
A partial delivery (at least one `done`) publishes exactly as before, and tasks (non-coding
cards) are unaffected.
