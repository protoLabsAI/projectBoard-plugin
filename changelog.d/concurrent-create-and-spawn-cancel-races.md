- **Cards created in parallel on a hot file always form one chain, and cancelling a Max-Mode sibling gate no longer orphans its process tree.** Hot-file chaining (#458) orders cards by `created_at`, but parallel `br create`s commit out of that order. A newer card could chain while an older one was not yet visible, and both then depended on the same tail without depending on each other, so the Ready gate refused one with a shared-file error. A card naming a hot file is now created and chained under the board's chain lock, so creation order and chain order match within a process. Cards that name no hot file still create in parallel. Separately, a cancel that landed while a repo command was still spawning (every Max-Mode sibling gate cancelled when another candidate's tree vanished) went to asyncio's own cleanup. That cleanup killed only the shell and then waited for its pipe. A child the shell had already forked kept the pipe open, so the cancel blocked for the child's whole run and left it running. Every subprocess the board spawns now goes through one guarded spawn: the loop's gates, fixups and acceptance commands (`spawn_shell`), the project-registration gate smoke, `git` and `gh` (`spawn_exec`), and the `lsof` cwd probe. On a cancel it finishes the spawn, kills the whole process group, and reaps it before it re-raises.
