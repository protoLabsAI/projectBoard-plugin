- **A leftover candidate branch or tree no longer blocks a card terminally (#475).** On
  bd-fgtf, every attempt blocked with `fatal: a branch named 'feat/bd-fgtf.g1' already
  exists`, five times in one night. Deleting the branch did not help, because the branch was
  not the cause. A removal interrupted half-way had left `.worktrees/feat-bd-fgtf.g1` as a
  husk: some files and no `.git`. The board called that directory clean and git would not
  remove it. `git worktree add` creates the branch before it checks the path, so each
  attempt created the branch and then failed on "already exists". Its one retry then failed
  on the branch it had just created, which hid the real error and left the branch behind for
  the next attempt. Now, when a candidate tree is created:
  - a husk with no `.git` is moved aside to `.worktrees/.stranded/`, with its files intact;
  - a leftover branch is reset onto the fresh base (`worktree add -B`), and any commits that
    exist nowhere else are first saved to a `stranded/…` branch;
  - a branch that another live worktree has checked out is left alone, and the candidate
    moves on to the next free `.g<n>`;
  - a failed add deletes the empty branch it created and reports the real error.

  Failed ladders and the by-id reap also delete candidate branches whose trees are already
  gone, after saving any unique work. A husk found by the reap or any other discard is
  cleared the same save-then-move way, so its unpushed commits and untracked files survive.
  A `worktree remove` of the board's own that hits its timeout after git took the `.git`
  link now finishes the removal, instead of leaving the next husk.
