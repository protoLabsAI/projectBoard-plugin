A stranded card's finished work can now be published without dispatching a coder.
`board_salvage_feature` and `POST /features/{fid}/salvage` commit what the card's worktree
holds, run the pre-PR gate, push the branch, open the PR and move the card to `in_review`,
using the board's own steps. It only works on a stranded card (`in_progress` with no live
drive, or `blocked`). It refuses while a drive owns the card, and when no worktree has
changes. A red gate publishes nothing and returns the gate output unless `force` is set,
which opens the PR as a draft carrying that output. Recovering bd-ezs7's 170 finished
lines had needed a coder, on the day the coder delegate was down. The tools reference also
lists `board_dispatch` now: the docs check skipped async tools, so it had shipped
undocumented.
