- **Done/cancelled cards stop alerting, and close edges clear their stale block/review
  labels (#536).** Operators were paged for cards that had already shipped — bd-g1d3 after
  PR #4184 merged, bd-b93u after #4177, nerdsville bd-5go after #41 — because
  `_notify_operator` deduped on an incident key but never asked whether the card was still
  open. It now re-reads the card right before writing the inbox row and DROPS the alert (at
  debug) for a `done`/`cancelled` card; a re-read that raises FAILS OPEN so a real block is
  never hidden. The re-read goes through the same store the sweep is already driving. Closed
  cards also kept stale labels (protoAgent bd-b4pr was `done` but still read `blocked: true`):
  `record_merge`, `mark_done`, and `cancel_feature` removed only `blocked` and left
  `blocked-class:*`, `in-review`, `review-pending` and `changes-requested` behind. All three
  now shed every live-state label through one shared `_terminal_stale_labels` helper, keeping
  the `cancelled` tag, the `review-clean` verdict and audit labels (`verified:`,
  `merged-verified:`, `self-verified`, …); the cancel edge folds the cleanup into its atomic
  tag write and re-adds every stripped label on a close-failure rollback. `board_list(state=
  "blocked")` is deliberately untouched — board_state maps the `blocked` FLAG, so a live
  blocked card is still listed and a `blocked-class:terminal` label with no flag stays a stale
  class, not a live block (#401).
