A provider that can't serve its model is now rotated past instead of climbed on. A retired
model, one the account's plan refuses, or one that needs a newer client used to classify as
`terminal`. In production the loop then escalated a tier on a provider failure, and a dead
provider listed at every rung was re-picked at each one while a working sibling sat idle. These
refusals are now their own `provider_unavailable` class, honoured only for a coder dispatch
failure. The loop switches to the next provider at the same rung, and later cards start on a
live sibling for 30 minutes. If every provider on the rung refused on that card, it blocks
under `dispatch-infra` naming them, without climbing; if some were only rate-limited, it blocks
as `rate_limit`, which self-heals. A fix round that hits a provider failure now keeps its
worktree, whether the next dispatch is a sibling or a quota retry, instead of rebuilding over
the implementation.
