- **A candidate that fails only on formatting is repaired in place instead of rebuilt (#719).** bd-j5qr2's first candidate was correct, but its gate ran `ruff format --check` before pytest, so pytest never ran and solve() built two fresh candidates (40+ minutes). New per-project settings `coder_solve_format_check_cmd` and `coder_solve_format_fix_cmd` add a format stage before the oracle: when the check fails, the fix command repairs the candidate in its own worktree (up to `coder_solve_format_repair_attempts`, default 1, at most 3), then the full oracle runs, behavioral tests included. A repair never counts as a generation. It shows in the live monitor's verify stages and in the solve log line. If the formatter touches files the candidate didn't change, fails, or doesn't converge, the candidate is put back as the coder wrote it and fails, with its tests reported as not run. A missing check or fix tool stops the search like a missing oracle and keeps the candidate. Both commands blank (the default) keeps today's behavior.
