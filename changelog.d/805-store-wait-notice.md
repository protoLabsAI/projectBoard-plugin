- **A board tool that had to wait for the board store now says so (#805).** Every `br` command in the process takes one lock, so a tool call made while the loop or the sweep is using the store queues behind it and answers late. A call that waited more than 2 seconds in total ends its reply with one line, for example `Waited 6.2 s for the board store (busy with other board work); the answer is current.`, so a slow answer reads as queued, not stuck. On a reply that carries a card or form component (`board_show_cards`, `board_card_form`) the line goes at the end of the text, before the component payload, so the card or form still renders. A call that did not wait replies exactly as before. The log gains a WARNING that names the `br` command that waited and for how long, separate from the existing slow-`br` warning, which still reports only the time `br` itself ran.
