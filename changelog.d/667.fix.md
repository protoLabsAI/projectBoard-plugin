A no-commit block now carries what the coder actually said. When a drive raises `NoChangesError` (coder produced no commits vs base), the handler reads the coder's final reply: an ordinary reply folds a bounded, whitespace-collapsed tail (≤ 1500 chars, the gate-red output-tail idiom) into the block reason and attempt record, so an empty run is no longer indistinguishable from a principled stop; an empty reply keeps today's message verbatim. A reply carrying a line that starts `BLOCKED-ON-<WORD>:` (e.g. `BLOCKED-ON-SPEC: …`) is treated as a DELIBERATE refusal — the coder judged the spec unbuildable as written — and blocks ONCE under a new non-self-healing `design` class, with no same-tier empty-result retry and no tier escalation (a stronger model would refuse the same gap); the reason quotes the marker line plus the rest of its paragraph, and the host-friction summary reads `coder refused: BLOCKED-ON-<WORD>` at minor severity instead of "nothing to open a PR from". True empty results, the empty-result retry (#198), and the external-bounce decline path (#653) are unchanged. Fixes #667.

Refusal markers tolerate multiple blank or whitespace-only lines before the marker. External-bounce no-commit rounds with tool activity retain the #653 terminal decline reason even when the reply includes a refusal marker, preserving the audited `--override-review` out-of-scope ruling.
