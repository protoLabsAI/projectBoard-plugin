An operator-opened PR can now be attached to the existing card it belongs to, with
`board_attach_pr` or `POST /features/{fid}/attach-pr`. Before, recovered work pushed by hand had
no way onto the board: the card sat blocked while its PR went through CI and review unseen, and
had to be closed by hand after the merge. The attach takes the same PR crash recovery would
adopt. It must be open, in the card's repo, on the card's own branch and against its base. The
card must be a coding feature that has passed the Ready gate, blocked or not, with no dependency
still open and no live coder drive. The card moves to review, and the normal loop runs CI, the
review gate and the merge. Any other shape is refused with the reason and leaves the card
unchanged. That includes re-attaching a blocked card's own PR, since unblocking stays a
deliberate step. The attached code has not been through the board's pre-PR checks; CI and the
review gate still apply. The health sweep now re-reads a card under the claim lock before it
requeues or adopts one, so it can no longer undo an attach it raced. The loop now reads a
`review_gate: "false"` setting as off, which it didn't before. The docs check covers async tools,
so `board_dispatch` is documented too.
