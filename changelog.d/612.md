- **Projects Configure page redesigned as compact rows with a checks dot and a side-panel editor (settings overhaul S2, #612).** **Settings → Plugins → Project Board → Configure → Projects** now lists one compact row per project — name, short repo path (home shown as `~`), base branch, a checks dot and a "default" marker — so about 14 projects fit roughly one screen and gate commands never clutter the list. The dot reads the loop's live preflight from `GET /status`: a held project is red and shows its one-line reason inline without opening the row; a project with a verdict and no hold is green; with nothing published yet (or the loop off) it is neutral. Clicking a row opens a side-panel editor where the local gate command and repo conventions sit under a collapsed, monospace, wrapped **Checks** section. The onboarding-root warning now appears only when adding is actually blocked and names the exact setting that unblocks it. Delete still needs a confirm and surfaces refusals (e.g. a 409) inline in plain words, and save semantics are unchanged (gate runs once on the clean base, 409 on a concurrent save, proxy-giveup read-back by request id). Both reads go through the authenticated plugin-kit fetch and the page loads only after `initPluginView`; colours come entirely from design-system tokens, so it works in light and dark.
