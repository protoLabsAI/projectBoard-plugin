- **The card-from-chat form is now a ready-made component, not model-written HTML.** The new `board_card_form(project="", title_hint="", why_hint="")` tool shows the board's new-card form inline in chat: a `board-card-form` frame component the plugin serves (`component/board-card-form.html`, ADR 0118 D5, public via `public_paths`). It's a single column that fills the card, with each label stacked over a full-width field: Project (a picker of the board's projects, hidden when there's only one; `project` preselects), Title, What & why, Acceptance criteria (one per line) and Priority (P0–P4, default P2). The fields start empty, and the hints become their placeholders. The form uses DS kit classes and `--pl-*` tokens only, and follows the console theme. **Create card** is a `type="button"` with no form submit. It validates the title, the what & why and at least one criterion, then proposes one compact message through the frame bridge's send path. The operator confirms it in the chat's ConfirmChip and it arrives as their next turn: `Create board card · <title>` / `Project: <name> · Priority: P<n>` / `Why: …` / `- <criterion>`. The form makes no reads and holds no board data. The `card-from-chat` skill now calls the tool right away and never writes HTML. It asks a follow-up only when the spec is genuinely ambiguous or a required detail is missing. It works out `files_to_modify` with read tools and doesn't add dependency edges to unrelated backlog cards unless the user asked. On a core without frame components, the tool tells the agent to ask for the fields in one message instead. The form appears in seconds instead of after 30–40 s of model output, and it looks the same every time.
