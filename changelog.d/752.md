- **Worktree reaping never removes a tree a live drive owns, and a merged card retires its recorded work locations (#752).**
  Two defects seen on mythxEngineer (2026-11-13). (1) A worktree vanished out from under a
  LIVE coder drive (friction f53268e9): `reap_feature_worktree` is called from many reconcile
  paths with no check that a drive still holds the feature's tree. Every reconcile reap now
  goes through one helper, `ReconcileMixin._reap_feature_worktree`, which defers the reap
  (logged once; retried on a later pass) while the loop holds a live drive for the card — the
  same in-flight drive registry `board_requeue_feature` refuses on — so a running drive's tree
  is never torn out, and the orphan sweep or a later pass reaps it once the drive ends. (2)
  After a card's PR merged and its tree was reaped, its recorded work locations still pointed
  at the deleted paths and the card read `[recovery] Recorded work needs recovery` with risk
  8–9. The merge edge (`record_merge`) now re-records each work-location entry whose path lay
  under the reaped tree with `retired: true` (the field #755 added), leaving entries elsewhere
  (a scratch repo, a pushed branch) untouched. Retirement is best-effort: any failure is
  logged and never blocks the close.
  Deferred merge cleanup also retires locations in the orphan sweep. The health sweep
  revisits done PR cards so retirement survives restarts, failed ledger writes, or a drive
  removing its own tree. Each location is retired only when its containing tree is gone:
  candidates kept because their work could not be saved remain active for recovery, even
  when the canonical reap succeeded. Candidate reap guards check the parent card's drive.
