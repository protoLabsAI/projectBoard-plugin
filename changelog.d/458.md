- **The shared-file gate accepts a dependency chain.** Two open cards naming the same file
  used to need a direct `depends_on` edge, so five cards on one `package.json` needed all
  ten pairwise edges, and the refusals came one card at a time. Any `depends_on` path
  through open cards now serialises a pair: a chain `E → D → C → B → A` orders A and E
  too, so five cards need four edges. The refusal lists every unserialised pair on the
  contended files and suggests the fewest edges that fix them: one chain per file,
  consistent with the edges already there, furthest-along card first, then creation order.
  It never tells a card that is already building to wait: a card with an open blocker
  can't close.
- **Cancelling a card keeps the order it carried.** In `C → B → A`, cancelling B used to
  release C to build beside A. Each open dependent that hasn't started building now gets
  a direct edge onto the cancelled card's open blockers first (`rewired_deps`).
- **Per-project `hot_files` are chained automatically.** A card created with a file that
  matches one of its project's `hot_files` globs (a workspace `package.json`, a barrel
  `index.ts`) gets a `depends_on` edge onto the open card at the end of that file's
  chain (among the cards created before it), noted on the card and reported as
  `hot_file_chain`. Racing creates are serialised. Empty by default.
