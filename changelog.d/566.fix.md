Prefix `feat: ` to a PR title only when the card's title does not already carry a conventional-commit type. The unconditional prefix double-typed any `chore:`/`fix:`/`docs:` card, and because that same string is the branch's commit subject — which GitHub uses verbatim for a single-commit PR's squash — a release card landed on main as `feat: chore: release v0.67.0`. `release.yml`'s `startsWith('chore: release v')` guard did not match, so the push-triggered run was skipped: a green merge, no release and no error. Correcting the PR title by hand does not help, because the subject comes from the commit.
