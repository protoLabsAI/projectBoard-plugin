- **An `oracle-timeout` block now KEEPS the card's worktree so `board_salvage_feature` can
  publish green work (#538).** When `coder.solve()` trips the acceptance-oracle timeout breaker
  (#459) the card is blocked `oracle-timeout` — a timeout says nothing about the code, so the
  build it judged is often green (bd-b4pr, a dependency bump whose build and tests passed). The
  drive used to `_discard_tree` that worktree, saving it to a `stranded/…` branch and removing
  it; `board_salvage_feature` (which publishes from a LIVE worktree) then refused with "no
  worktree of <id> has changes vs main". Now, alone among the block classes, the OracleTimeout
  path keeps the worktree — the same keep-the-work stance the closed-source-issue guard takes
  (protoAgent#3832) — and leaves a comment naming the tree path and the salvage
  (`board_salvage_feature` / `POST /features/<id>/salvage`) that can publish it, or a cancel if
  the work is unwanted. Nothing reaps the tree meanwhile: the health sweep's reaper only takes
  `done`/`cancelled`/gone trees, and `oracle-timeout` is not self-healing, so the blocked sweep
  neither requeues nor removes it — it waits for a human to salvage or cancel. Every other block
  class keeps its existing discard behaviour, and the oracle budget
  (`coder_solve_test_timeout_s`) is unchanged.
