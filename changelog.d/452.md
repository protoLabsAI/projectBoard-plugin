- **Registering a board project makes it a read-only managed project (#452).**
  `board_register_project` and `PUT /projects/{name}` used to write only
  `project_board.projects`, so the lead agent's filesystem tools could not read the checkout
  its coders branch from. They now also add a read-only entry to the host's managed-projects
  registry (ADR 0095 `projects:`): `github` comes from the `origin` remote and
  `default_branch` is the base branch. It goes in the same `HOST.apply_settings` patch,
  shaped like `onboard_project`'s. An entry that already exists is left alone. Unregistering
  removes the entry only if the board added it and it still points at the board's repo.
- **Base checkouts are fast-forwarded (#452).** Each health sweep fetches every project's base
  branch and runs `merge --ff-only` on the MAIN checkout, but only when it is clean, on the base
  branch, and has nothing the remote lacks. The board never resets, stashes or switches
  branches. Any other checkout is left as it is and listed under `stale_base_checkouts` on
  `GET /status`. The new `base_refresh` knob (default on) turns this off.
