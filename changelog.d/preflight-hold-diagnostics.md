- **A preflight hold now says which step of the gate failed and what it printed.** Three designSystem cards (ds-n8d, ds-tqo, ds-rf6) sat `blocked:preflight-hold` reading only "the coder environment can't run the gate: Exit status 1". Their gate is `pnpm install --frozen-lockfile && pnpm -r typecheck && pnpm -r test`. The hold stamped the output's last line, which is pnpm's sign-off, and the full output went only to the daemon log, which the agent can't read. Now the preflight prints a marker before each step of a plain `&&` chain; the chain and its exit status are unchanged. The card's `blocked_reason` names the failing step and the most telling output line, such as `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL @ds/core typecheck: …`. Each held card also gets one `gate preflight output` comment per distinct failure (timings, timestamps and npm log paths do not make a failure distinct, and a restart does not repeat the comment), with the step, the exit status and the last 30 lines of output, credentials redacted. The same detail is on `/status` (`preflight.failures`), on `board_get_feature` (`preflight_failure`) and on `board_dispatch` (`held["blocked:preflight-hold"].preflight_failures`).
